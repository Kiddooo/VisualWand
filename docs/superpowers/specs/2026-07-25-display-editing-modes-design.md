# Display Editing Modes Design

## Goal

Replace direct transformation buttons and the separate gizmo transformation workflow with one server-authoritative editing session. The GUI selects a mode; ordinary left click applies the positive operation and ordinary right click applies the negative operation. Only an active mode consumes those clicks.

The plugin remains server-only. It uses Paper interaction events generated by normal client controls and requires no client mod or custom networking layer.

## Existing Systems and Migration Boundary

The project currently has three overlapping transformation state owners: `EditorSession`, `GizmoSession`, and `WandListener.TransformSession`. `TransformMenuGUI` also mutates entities directly. The refactor makes `EditorManager` the only owner of display selection and editing state.

Existing strict display targeting, `visualwand.use`, Bukkit transformation writes, glow restoration, entity-specific property menus, and animation management remain. Direct transform callbacks, mouse-wheel transformation sessions, and independent gizmo mode state are removed. Gizmo rendering may remain as visual feedback, but it reads the editor session and never owns mode or selection state.

## Session State

One `EditorSession` exists per editing player and stores:

- selected world and display UUID;
- active `EditMode`, nullable until the player chooses one;
- active `StepPreset` (`FINE`, `NORMAL`, or `COARSE`);
- input repeat state for positive and negative clicks;
- one immutable snapshot for undo;
- the last feedback value;
- whether an input pulse is currently being consumed.

Transformation components are defensively copied because Bukkit/JOML values are mutable. A per-player clipboard in `EditorManager` stores a copied Bukkit `Transformation`; it does not store the entity's world location or entity-specific properties.

`EditorFeedback` reuses the project's reference-counted glow pattern. It records one original glow value per selected display and restores that value only after the final editor deselects it, so concurrent viewers cannot clear each other's selection feedback.

Selecting another display replaces the session, clears the active mode and undo snapshot, opens the mode menu, and retains the player's step preset. This prevents an old mode from changing a newly selected entity accidentally. Deselecting or cancelling removes the whole session.

## Mode Model

`EditMode` is a declarative enum implementing a common mode contract. Each entry defines:

- display name and GUI material;
- category;
- axis and quaternion side where applicable;
- required step type;
- positive and negative operation;
- applicability predicate;
- value formatter for feedback.

Modes are:

- Move X, Move Y, Move Z;
- Left Rotation X, Left Rotation Y, Left Rotation Z;
- Right Rotation X, Right Rotation Y, Right Rotation Z;
- Scale X, Scale Y, Scale Z, Uniform Scale;
- Entity Yaw and Entity Pitch.

All modes apply to Block, Item, and Text Display entities. Entity-specific properties remain in their existing menus.

## Transformation Semantics

### Translation

Movement preserves existing behavior by changing the entity's world location along world X, Y, or Z. Yaw and pitch are preserved during teleportation. Translation reset is explicitly named **Reset Transform Translation** and resets the Bukkit transformation translation vector to zero; it does not move the entity back to an unknown historical world position.

### Rotation

The existing editor rotates the transformation's left quaternion, so the primary rotation modes remain left-rotation modes and are labeled accordingly. Right rotation receives separate X, Y, and Z modes.

Each operation creates an axis-angle delta quaternion, composes it with a defensive copy of the selected side, and normalizes the result. Quaternion components are never treated as Euler angles. The other rotation, translation, and scale values are preserved exactly. Feedback reports the side, axis, step, and signed last delta rather than decomposing an arbitrary quaternion into unstable Euler angles.

Entity Yaw and Entity Pitch use the entity location rotation and are separate from both transformation quaternions. Angles are normalized to a stable display range.

### Scale

Scale edits use a configured additive magnitude step on one axis or all axes. Existing negative axes remain negative, preserving mirrored displays. Editing changes magnitude without crossing zero, so it cannot accidentally toggle mirroring. Every axis magnitude is clamped to configured minimum and maximum values, defaulting to `0.01` and `100.0`. Non-finite source or result values reject the operation.

## Step Configuration

Configuration contains centralized preset values:

- translation: `0.01`, `0.1`, `1.0`;
- rotation: `1`, `5`, `15` degrees;
- scale: `0.01`, `0.1`, `0.5`;
- entity rotation uses the rotation preset;
- scale minimum and maximum;
- input initial delay, repeat interval, release-gap reset, and maximum accepted update rate.

Configuration loading validates finiteness, positivity, ordering, and safe tick intervals once. Invalid values log a warning and use defaults. Mode code never embeds step values.

## Click Input

With a valid selected display and active mode:

- left click applies one positive edit;
- right click applies one negative edit;
- the triggering interaction is cancelled;
- block damage and breaking, entity damage, entity interaction, item use, and block placement associated with the consumed click are cancelled without applying a second edit.

With no active mode, input is untouched even if a display is selected.

The first click applies immediately. Vanilla repeated click events from a held button pass through a per-direction gate: pulses before the configured initial delay are ignored, then at most one pulse per repeat interval is accepted. A configurable no-input gap resets the gate so the next click is a new immediate press. Operations are never synthesized without an input event, preventing edits after release and avoiding frame-rate-dependent scheduler repetition.

The wand's Drop control is cancelled and reopens the mode menu while a session exists. Persistent feedback names this control. It does not transform the entity.

## Validation and Authority

Before every edit and during periodic session maintenance, `EditorManager` re-resolves the stored entity UUID and validates:

- the player is online and still has `visualwand.use`;
- the world matches the selected world;
- the entity is loaded, valid, and a supported Display subtype;
- the entity is within `editor.max-distance`;
- input passes the configured rate limit;
- current and resulting location/transformation components are finite;
- scale and configured bounds are valid.

Failure clears the session, restores temporary visual state when possible, and informs an online player. Player quit and world change clear the session immediately. Removed or unloaded entities are detected by event handling where available and by the maintenance task otherwise.

The input request never supplies an entity identity; the server applies it only to the UUID stored in its session. Bukkit `teleport` and `setTransformation` are the authoritative writes and synchronize observers. Equal before/after states produce no entity write and no undo replacement.

## GUI and Feedback

`TransformMenuGUI` becomes a 54-slot mode-selection menu. It groups movement, left rotation, right rotation, scale, and entity orientation with distinct labels. Fine, Normal, and Coarse controls show the active preset. Utility controls are visually separated from modes.

Selecting a mode stores it, closes the inventory immediately, enables the selection glow, and sends instructions. Selecting a preset keeps the GUI open so another preset or mode can be chosen. Utilities are deliberate GUI actions:

- Reset Transform Translation;
- Reset Rotations;
- Reset Scale;
- Reset Entire Transformation;
- Copy Transformation;
- Paste Transformation;
- Undo Last Change;
- Cancel Editing;
- Deselect Entity.

Every mutating reset and paste captures an undo snapshot. Reset rotations sets both left and right quaternions to identity but does not change entity yaw or pitch. Reset Entire Transformation uses zero translation, identity rotations, and unit scale. Cancel and Deselect both end the current session; Cancel is the user-facing editing exit, while Deselect explicitly emphasizes clearing selection.

While a mode is active, an action bar periodically shows selected display type and UUID suffix, mode, category-specific step, signed last change, useful current value, and the menu-reopen control. The selected entity glows throughout the editing session; reference-counted cleanup restores its original glow state after the final editor leaves.

## Component Boundaries

- `EditorManager`: session lifecycle, clipboard, dispatch, maintenance, and authoritative orchestration.
- `EditorSession`: one player's selected entity, mode, preset, repeat state, undo, and feedback state.
- `EditMode` and related enums: declarative mode metadata.
- `EditorConfiguration`: validated step, scale, repeat, distance, and feedback settings.
- `TransformationOperations`: pure location/transformation calculations and safe quaternion composition.
- `EditValidator`: permission, entity, distance, finite-value, and bounds checks.
- `EditorInputListener`: left/right click routing and normal-action cancellation.
- `TransformMenuGUI`: mode/preset/utility selection only.
- `EditorFeedback`: action-bar formatting and glow lifecycle.
- `WandListener`: creation, strict targeting, selection, deletion, and menu entry; no transformation state.
